GPU Memory / Virtual Memory / Unified Memory

Memory Owner 的长期纵深路线：切入 → 深化 → 拓展 → 演进。

阶段 1 · 切入：Recoverable Fault + HMM + Migration + Replay

目标不是做零散 helper，而是打通 GPU fault → PASID/VM/context → mm_struct/HMM → residency/migration → GPU PTE → TLB invalidate → replay 的完整闭环。

  • fault classification / PASID lookup / process lifetime
  • mmu_notifier / HMM / CPU PTE state
  • CPU↔VRAM migration / copy engine
  • GPU PTE update / TLB ordering / replay
  • duplicate fault / concurrent fault / teardown / reset races

3–6 个月交付：一个可调试的单 GPU pageable-memory 完整 fault/migration/replay 路径，并具备稳定 tracepoint 和错误回滚。

阶段 2 · 深化：GPUVM + Migration Granularity + Oversubscription

从‘能 fault/migrate’升级到可扩展的 GPU memory subsystem。重点是 GPUVM 生命周期、page-size abstraction、TLB batching，以及在 VRAM pressure 下反复 migrate/evict/repopulate。

  • GPU VA / VMID / PASID / sparse mapping / large pages
  • CPU base page ≠ migration unit ≠ DMA map unit ≠ GPU PTE unit ≠ TLB unit
  • 4K correctness → batched 4K → 64K/HW-native → 2M/compound/higher-order DMA
  • VRAM accounting / eviction / reclaim / oversubscription
  • working-set and mechanism/policy separation

6–18 个月交付：可在压力下持续 fault/migrate/evict 的 memory subsystem，并为大页/compound migration 保留架构能力。

阶段 3 · 拓展：SVA/IOMMU + NUMA + Cross-device Memory

把视角从 GPU 本地 MMU 扩展到 CPU+GPU+IOMMU 的系统地址空间和放置拓扑。

  • PASID / SVA / ATS / PRI / device-TLB invalidation
  • IOMMU page table vs GPU page table ownership
  • NUMA-aware host memory placement and migration
  • dma-buf export/import / peer-visible memory / cross-device lifetime
  • 与 Multi-GPU owner 的边界：对方负责 topology/connectivity/peer transport；Memory 负责 residency/lifetime/migration/shared-VM policy。

1–2 年交付：形成 CPU VA、GPUVM、IOMMU/SVA 与 peer-visible memory 之间清晰的 ownership 和 placement 架构。

阶段 4 · 演进：Multi-GPU UVM + Tiered/CXL + Policy

最终从机制 owner 演进为 heterogeneous-memory architecture owner。

  • per-GPU residency / GPU↔GPU migration / replication
  • shared VA / shared VM / concurrent multi-GPU faults
  • CPU DRAM / GPU VRAM / peer VRAM / CXL or pooled-memory tiers
  • hot/cold placement / preferred location / access counters
  • migration thresholds / memory QoS / tenant accounting
  • 原则：mechanism before policy；lifetime/correctness before optimization；single-GPU closure before multi-GPU policy。

2–5 年目标：成为 GPU Memory / UVM / Heterogeneous Memory Architecture Owner，能跨 Linux MM、DRM/GPUVM、IOMMU、FW、copy engine、multi-GPU topology 和 HW MMU 做系统级决策。

推荐推进顺序

GPUVM → mmu_notifier/HMM → recoverable fault → migration/replay → migration granularity → eviction/oversubscription → IOMMU/SVA → NUMA/P2P memory → multi-GPU UVM → tiered/CXL → policy/QoS
