# 2026-09-05 Weekly #4 — Recovery Contract / VFIO AER / Telemetry Service

## Key decisions

1. **No taxonomy change.** Keep the seven stable Owners.
2. **Memory remains P0:** recoverable fault + HMM + migration + replay, with invalidation/generation/measurement correctness.
3. **RAS deepens from a reset gate into a reusable Recovery Admission / State / Sequence Contract.**
4. **Virtualization absorbs the VFIO PCI-error-recovery model:** host recovery state, access revocation/guarding, reset completion and sequence must be visible to a VMM instead of a semantically empty event.
5. **Observability/Power/Firmware absorb Xe Crescent Island PMT lessons:** telemetry/crashlog access has its own shared-window arbitration, runtime-PM lifetime, FW readiness, hotplug and SR-IOV boundary.
6. **Multi-GPU remains topology/port/peer first.** No new direction-level fabric signal this week exceeds the existing DRM Fabric + AMD UALink work.

## Highest-value new industry signals

### VFIO PCI error recovery RFC — 2026-09-01
Source: https://lwn.net/Articles/1091953/

The RFC extends generic vfio-pci from a one-shot error event toward a real host-recovery contract: `error_detected()` records severity, blocks/revokes device access, quiesces interrupts and publishes state; `slot_reset()` restores configuration after host reset; `resume()` restores access. A new opt-in uAPI carries status bits plus a sequence number so a VMM can distinguish non-fatal recovery, reset, frozen channel and permanent failure even when recovery finishes before userspace handles the event.

KMD impact: reuse the same pattern for GPU reset/recovery: explicit admission gate, recovery state, monotonic sequence/generation, fail-safe stale-access behavior and clear post-recovery validity semantics.

### Intel Crescent Island PMT v4 — 2026-09-01
Source: https://lwn.net/Articles/1092225/

Xe registers PMT for Crescent Island GPU. PMT features share an MMIO access window requiring driver callbacks/index selection; crashlog/telemetry access depends on device power; firmware is loaded at device power so PMT uses late binding for FW readiness; hotplug, lock ordering and SR-IOV VF behavior are also handled.

KMD impact: telemetry should be a service boundary, not direct consumers owning raw MMIO windows. Centralize PM lifetime, FW readiness, privilege/VF filtering, shared-window arbitration and access serialization.

### Tyr VM/BO ioctl series — 2026-09-02
Source: https://lwn.net/Articles/1091992/

Tyr adds per-file VM pools and VM/BO ioctls aligned with Panthor, based on the Rust DRM `drm-file` work. This is a useful Future Topic signal that Rust GPU drivers are moving into real VM/uAPI implementation, but it does not change the Memory Owner entry feature.

### Rust typed register projections v4 — 2026-09-01
Source: https://lwn.net/Articles/1091993/

The series updates both Tyr and nova-core to use typed register projections instead of relative-register arithmetic. Treat it as future engineering infrastructure for safer register-block ownership, not as a new Owner.

## Durable learning-resource additions

### Virtualization / VFIO
Add the VFIO PCI error-recovery RFC as an Implementation/evolving-uAPI reference. Study access guards, BAR fault retry, DMA-BUF revocation, status+sequence uAPI, AER callbacks, lock ordering and fault injection. Do not treat the current RFC bits as frozen ABI.

### Observability / GPU PMU
Add Crescent Island PMT v4 as an Implementation/platform-telemetry reference. Study shared indirect-window arbitration, PM lifetime, FW late binding, crashlog-vs-telemetry access, hotplug and VF boundaries. Extract the service-ownership model rather than copying Intel PMT APIs.

## Deep-dive feature

Define one `recovery_state` object with a monotonic sequence, phase, scope, reason and health result. Access paths call semantic admission APIs rather than reading a `resetting` boolean. On recovery: publish QUIESCING and close admission; drain active users; freeze evidence; perform reset without holding the recovery-state lock; restore; publish NORMAL or FAILED; wake/retry clients. Every long-lived async object revalidates its recovery/FW/VM generation before publishing state or completing work.

## Leader Memory deep dive

Apply the Recovery Contract to the fault worker. A successful HMM walk or migration copy is insufficient if `recovery_seq`, VM/context generation or MMU-notifier sequence changed before PTE publication/replay. TLB-invalidate completion and replay must also be generation-aware so a late completion from the old GPU world cannot complete a request in the new world.
