# GPU KMD Owner Direction — 2026-09-12 Weekly #5

## 本期核心判断

- 七个一级 Owner taxonomy 不变。
- Memory 当前 P0 仍是 recoverable fault + HMM + migration + replay correctness；新增明确 P1：**VRAM Pressure + Reclaim / Eviction Contract**。
- RAS 从 Recovery Admission/State/Sequence 继续扩展到 **Recovery Scope + Escalation**，覆盖 context/queue/engine/FW/device warm/PCI/cold reset/permanent failure。
- Virtualization 在 SR-IOV hardware gate 通过后，应从第一版就为 VF state serialization / restore 留出边界；multi-queue migration 说明 queue 不是天然独立迁移单元。
- Observability 把 stable object/event identity 深化成 structured error schema，让 trace/eBPF/devcoredump/FW log/management event 共用 identity。
- Firmware 第一版协议必须显式定义 authoritative protocol state，避免 software shadow 与 mailbox/ring hardware/FW state 漂移。

## Owner Living Updates

### Memory
1. Linux device-memory cgroup 已定义 `dmem.max/min/low/current/capacity`，TTM/Xe/AMDGPU reclaim 已形成机制；IGT v6 新增同步 eviction、interruptible eviction 和 `O_NONBLOCK` eviction 测试。意义：显存 pressure/accounting/protection/reclaim/QoS 可以被拆成独立 KMD capability loop。
   - Sources: https://www.kernel.org/doc/html/v7.0/admin-guide/cgroup-v2.html ; https://www.mail-archive.com/dri-devel@lists.freedesktop.org/msg632941.html
   - Priority: P1 after recoverable-fault/HMM correctness.
2. Xe CPU-bind + ULLS migration-queue work treats page-fault latency as a first-class target and separates page-fault bind ordering from ordinary migration queues.
   - Priority: measurement P0; dedicated low-latency path P1.

### Virtualization / Security
1. Xe next work extends VF migration toward multi-queue. Existing migration state already spans GGTT/MMIO/GuC FW/VRAM; multi-queue adds queue-group and scheduler-state relationships.
   - Impact: define stable logical resource IDs and serialize/restore boundaries in early PF/VF architecture.
   - Priority: architecture P1; full live migration later.

### Power / Performance
1. AMD Apple Navi14 UCLK DPM had to be deferred from initial feature-enable to post-init because early enable could timeout and prevent DRM-device creation.
   - Impact: `supported != safe to enable now`; model capability, readiness, safe phase, ACK, post-validation and rollback.
   - Priority: current PM/FW interface design.

### Reliability / Recovery / RAS
1. Xe adds `DRM_WEDGE_RECOVERY_COLD_RESET` for persistent hardware state that ordinary reload/PCI reset cannot clear.
   - Impact: formalize recovery hierarchy and escalation semantics.
2. AMD gfx1150 7.3-rc1 regression shows an initially similar permission fault can either stay context-local or escalate into MES/KFD-wide failure depending on recovery path.
   - Impact: validate recovery outcome/containment, not only whether reset was triggered.
   - Priority: current RAS/fault-injection work.

### Multi-GPU / P2P / Fabric
本期无高价值方向级新增。保持 topology/control-first，继续 stable identity → endpoint/port/peer → directional P2P capability → peer mapping/data path。

### Observability / Profiling
1. DRM_RAS netlink event, error threshold and structured SIGID work pushes GPU error reporting toward stable node/error identity plus userspace-consumable policy.
   - Impact: define object/error/event identity, severity, generation, counter, threshold and recovery result once and reuse it across tracing, eBPF, devcoredump and management.
   - Priority: P0/P1 schema work.

### Firmware / Control Plane
1. Xe system-controller mailbox PHASE fix removes a drifting software shadow and reads the authoritative hardware phase before each frame.
   - Impact: every shared protocol field must have one authoritative owner/truth source; reset/reconnect rules must say what is reread, re-handshaken or regenerated.
   - Priority: first protocol design.

## 本期重点 Feature

### VRAM Pressure + Reclaim / Eviction Contract

First-stage mechanism:

```text
usage accounting
→ pressure watermark
→ select evictable residency
→ synchronize active access
→ allocate destination
→ copy
→ publish new mapping
→ TLB completion
→ release old backing
→ reclaim completion
```

Keep mechanism separate from policy. Begin with deterministic/manual reclaim and simple LRU; later add per-process/cgroup protection, hotness, large-page/NUMA awareness, multi-GPU and tiered/CXL policy.

The key architectural bridge is to make fault and eviction share the same residency/migration/PTE/TLB/generation primitives:

```text
Fault:    System → VRAM
Eviction: VRAM   → System
```

## Team Recommendation

For a 5–6 person KMD team:
- Leader / Memory: recoverable fault/HMM P0 + next-stage reclaim contract design.
- RAS: snapshot + recovery admission/state/sequence + scope/escalation.
- Firmware: versioned protocol + capability/generation/readiness + authoritative-state rules.
- Multi-GPU: stable identity/topology/port/peer/directional capability.
- Observability: stable object/error/event IDs + counters/eBPF/structured RAS events.
- Conditional sixth: SR-IOV provisioning/migration groundwork if ASIC supports it; otherwise Power/runtime PM.

## Leader Memory Deep Dive

Study **Fault × Reclaim** races on the same page/range. A long-term state model should distinguish at least:

```text
SYSTEM_RESIDENT
→ MIGRATING_TO_GPU
→ GPU_RESIDENT
→ MIGRATING_TO_SYSTEM
→ SYSTEM_RESIDENT
```

with side/lifetime states such as `PINNED`, `INVALIDATING`, `STALE_BY_RESET`, and `DESTROYING`. Correctness must be proven across fault, migration, eviction, MM invalidation, context teardown and GPU reset; one page/range must always have one authoritative, recoverable residency state.
