# 2026-08-08 Test #3 — Resource Model R2

This is a re-publication of Test #3 after revising the durable Learning Resource model. Technical Owner conclusions and Industry Updates are unchanged.

## Resource-model revision
- Old model: one resource file per top-level Owner, with all sub-directions mixed together.
- New model: **one independent Markdown file per stable sub-direction** under `resources/<owner>/<sub-direction>.md`.
- Every resource entry now records: what it is, why it is valuable, what to focus on, study cautions and the source link.
- Sub-direction learning files are stable-growth documents: add by default; rewrite only when a resource is obsolete/superseded or the sub-direction is explicitly redefined.
- GitHub Pages now exposes a unique learning-page URL for every sub-direction and renders from the corresponding Markdown source-of-truth.
- Industry Updates remain at the top-level Owner and continue to refresh every run.

## Test #3 technical conclusions retained
1. Memory: recoverable fault + HMM + migration + replay; preserve migration-granularity abstraction and N:1 multi-device compatibility.
2. Firmware: versioned async protocol + capability negotiation + restart/state reconciliation; firmware-version independence is a core invariant.
3. RAS: snapshot/devcoredump + FW logs + reset reason before destructive recovery.
4. Multi-GPU: stable identity/topology/P2P capability before shared VM.
5. Observability: stable event/object identity + eBPF trace; PMU joins the same timeline later.
6. Virtualization: SR-IOV remains ASIC-capability-gated; focus on resource provisioning/isolation, not generic PCI enable calls.
7. Power: reusable telemetry first; complex governor later.
