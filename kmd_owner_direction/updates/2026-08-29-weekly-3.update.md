# GPU KMD Owner Direction — 2026-08-29 Weekly #3

## Theme
**Fabric becomes concrete: topology object model + remote memory invalidation + stable firmware ABI boundaries.**

Seven-owner taxonomy remains unchanged.

## Highest-value changes
1. Memory keeps recoverable fault/HMM/migration/replay as P0, but future multi-GPU invalidation is now modeled as a separate remote mapping/connection protocol rather than an extension of one local TLB flush.
2. Multi-GPU Living entry is strengthened to stable identity + topology/port/peer model + directional P2P capability matrix, informed by AMD UALink and DRM Fabric RFC.
3. Firmware explicitly adds a raw-FW-ABI → parser/validator → translation/capability → stable KMD service boundary, informed by Nova r000 GSP ABI work.
4. Power adds IRQ/FW/workqueue quiesce ordering as a first-class runtime-PM correctness requirement.
5. RAS preserves reset gate/generation and reserves separate fabric/connection generations for future multi-GPU recovery.

## Industry update highlights

### Memory / Multi-GPU
AMD's 2026-08-21 UALink series introduces NPA remote memory, export/import authorization, remote TLB shootdown, remote interrupt, connection reset and peer PTE mapping. Exported memory is not permanently pinned: TTM eviction/MMU notifier may revoke or move it, forcing importer invalidation/retry.

### Multi-GPU / Fabric
The 2026-08-24 DRM Fabric RFC proposes vendor-neutral topology objects:
`fabric → endpoint → port → peer`.
It separates common identity/topology/state from vendor-owned firmware, memory semantics and data path.

### Firmware
Nova r000 GSP ABI v2 moves from release-specific 570.xxx firmware to a stable r000 ABI, changing MCTP/NVDM transport, msgq v2, load-exec/GSP_INIT boot flow, buffers and validation as one major protocol transition.

### Power
A current Imagination GPU runtime-PM fix requires synchronizing IRQ handlers before suspend, showing that PM correctness requires asynchronous access quiescing, not just PM-reference accounting.

### Observability
DAMON/perf hardware-sampling observability RFC uses per-CPU pipeline counters, debugfs stats and tracepoints to expose where an async sampling pipeline stops. Apply the same principle to future GPU PMU/fabric event pipelines.

### Virtualization
No new GPU-specific SR-IOV mechanism changes the hardware-gated plan.
