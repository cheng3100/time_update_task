# 2026-08-15 GPU KMD Weekly Owner Direction Update

## A. 本期最值得新增/增强的 Feature

1. **Memory — Recoverable Fault Measurement Contract**：在既有 recoverable fault + HMM + migration + replay 主线不变的前提下，把 fault/migration measurement schema 提升为第一阶段正式 deliverable。参考 Xe GT Statistics，将 page-fault、get-pages、CPU↔device copy、GPU bind、TLB invalidation 按 page size/granularity 拆分。
2. **RAS — GPU Health State / Recovery Hint Contract**：在 frozen snapshot + devcoredump 之后增加稳定 device-health 状态与 management-facing recovery hint，使监控/运维层知道 GPU 是 ok/warning/critical、应 rebind/bus-reset 还是需要 firmware remediation。
3. **Firmware — Boot/Reset Phase & Generation Model**：把 control plane 从“消息协议”进一步明确为 boot/reset phase state machine：secure FW/devinit/GFW_BOOT/host service ready/restart generation/state reconciliation。
4. **Observability — Low-overhead KMD Software Counters + Unified Object IDs**：把 per-CPU software statistics 作为 tracepoint/PMU 之外的第一层低开销 telemetry，并保证后续可以和 PID/PASID/VM/context/queue/job timeline 关联。
5. **Multi-GPU — topology/P2P capability contract 保持优先**：本期没有证据支持提前跳到 shared-VM/fabric programmable policy；继续先建立稳定 identity/topology/peer capability。

## B. 七个 Owner + 子方向雷达

### 1. Memory / Virtual Memory / Unified Memory
稳定子方向：GPUVM/page table/VMID/PASID/TLB；recoverable fault/replay；mmu_notifier/HMM/SVM/device-private；CPU↔GPU migration/oversubscription/eviction；NUMA/large & compound pages/migration granularity；IOMMU/ATS/PRI/PASID/SVA；dma-buf/P2P memory；multi-GPU UVM/tiered memory。
当前优先级：fault/replay correctness=P0；measurement schema=P0；migration granularity=P1；oversubscription/eviction=P1/P2；multi-GPU UVM=后续。

### 2. Virtualization / Security
稳定子方向：VFIO/ownership/IOMMU isolation；SR-IOV PF/VF；resource partition；PF↔VF ABI/VF FLR；vGPU/live migration；secure boot/measurement/scrub/attestation。
当前优先级：ASIC capability assessment=P0；真实 SR-IOV HW 存在时 provisioning/isolation=P1；CXL Type-2 passthrough=长期观察。

### 3. Power / Performance
稳定子方向：busy/idle/utilization；runtime PM；clock/power gating；DVFS/OPP/FW PM；thermal/power cap；frequency/memory-bandwidth telemetry。
当前优先级：measurement/lifetime correctness=P0/P1；basic DVFS/runtime PM=P1；复杂 governor 后置。

### 4. Reliability / Recovery / RAS
稳定子方向：heartbeat/watchdog；snapshot/devcoredump/reset reason；job/queue/context/engine recovery；restore/replay；FW crash/log retention；ECC/bad-page/AER/fault injection。
当前优先级：frozen evidence=P0；health-state contract=P1；recovery granularity=P1/P2。

### 5. Multi-GPU / P2P / Fabric
稳定子方向：identity；visibility/affinity；PCIe/NUMA/switch topology；P2P capability；peer BAR/PTE；P2P DMA/dma-buf；shared VA/multi-GPU VM/fabric health。
当前优先级：identity/topology/P2P matrix=P1；peer mapping/P2P DMA=P1/P2；shared VM/fabric policy=后续。

### 6. Observability / Profiling
稳定子方向：tracepoint schema；BTF/CO-RE/eBPF；object correlation；UMD→KMD→FW→GPU timeline；PMU；perf_event/dynamic diagnostics/programmable hooks。
当前优先级：stable object/event model=P1；software counters=P1；PMU integration=P1/P2；programmable policy=长期。

### 7. Firmware / Control Plane
稳定子方向：versioned ABI；transport；async completion/error；capability negotiation；boot/restart/upgrade/rollback；resource ownership/state reconciliation；FW-centric PM/reset/scheduler services；FW health/security。
当前优先级：version/capability/async contract=P0；boot/reset generation state machine=P0/P1；health/log service=P1。

## C. 每个 Owner 当前切入点

- Memory：Recoverable fault → PASID/VM/context lookup → HMM/CPU PTE resolution → optional migration → GPU PTE → TLB invalidate → replay；第一版同时记录可量化阶段耗时和 race/generation 状态。
- Virtualization：SR-IOV HW capability gate；没有真实 partition/reset/isolation 能力就只做 VFIO/reset/ownership assessment。
- Power：可靠 busy/idle + per-engine utilization → reusable telemetry → DVFS/runtime PM。
- RAS：hang detect → freeze structured evidence → devcoredump → health state/recovery hint → reset/restore。
- Multi-GPU：stable identity → topology graph → visibility/affinity → P2P capability matrix。
- Observability：stable device/client/PID/PASID/VM/context/queue/job IDs + tracepoints + low-overhead software counters。
- Firmware：Versioned async protocol + capability negotiation + boot/reset generation + re-handshake/state reconciliation。

## D. Industry Updates

### Memory
**本期首次纳入高价值近期信号：Xe GT Statistics。** Linux `next-20260722` 的 Xe GT statistics 已经提供 `svm_pagefault_count`、TLB invalidation、4K/64K/2M fault count/time、CPU→device migration count/time、CPU/device copy time/bytes、get-pages time、GPU bind time，以及 page reclaim list counters。来源：https://docs.kernel.org/next/gpu/xe/xe_gt_stats.html

KMD 影响：migration granularity 不应只在 roadmap 上写“未来做 64K/2M”，而应现在就定义 measurement contract。第一版 4K correctness 完成后，用完全相同的指标比较 batched-4K/64K/2M，才能判断瓶颈来自 core-MM、DMA map、copy engine、PTE bind 还是 TLB。
优先级：**measurement schema 现在；64K/2M prototype 在 6–12 个月。**

GPU SVM / drm_pagemap 仍继续强调 range/notifier、migration、device-private memory、N:1/per-device mapping view 和 future multi-GPU；没有发现本周足以改变既有架构判断的新 patchset。来源：https://docs.kernel.org/next/gpu/rfc/gpusvm.html

### Virtualization / Security
**本期无高价值新增。** 当前 Xe configfs 仍是最具体的 GPU SR-IOV lifecycle 参考：`sriov/max_vfs` 在 bind/probe 前决定 PF mode 和可管理 VF 数量，并且当前 `next` 还暴露 admin-only-PF 等内部配置读取接口。来源：https://docs.kernel.org/next/gpu/xe/xe_configfs.html

KMD 影响：结论不变——SR-IOV owner 的核心是 pre-probe resource mode、VF resource provisioning、PF↔VF ABI、reset/isolation，而不是 `pci_enable_sriov()`。
优先级：**ASIC capability first。**

### Power / Performance
**本期无高价值方向级新增。** Xe Runtime PM 当前文档继续强化 outer-level PM reference：IOCTL、sysfs/debugfs、dma-buf sharing、GPU execution 等从高层持有 runtime-PM reference；D3Cold 还受 VRAM usage/PCI hierarchy 等约束。来源：https://docs.kernel.org/next/gpu/xe/xe_pm.html

KMD 影响：Power feature 仍应先解决 lifetime/reference correctness，再做 governor。PM reference、memory reclaim、suspend/resume 和 VRAM lifecycle 的交互比“调频算法”更早。
优先级：**现在。**

### Reliability / RAS
**本期首次纳入高价值近期信号：Xe GPU Health Indicator / Device Wedging。** Xe 通过 `/sys/bus/pci/devices/<device>/gpu_health` 暴露 `ok/warning/critical`，并通过 DRM wedged uevent 区分 rebind/bus-reset 或 vendor-specific recovery，例如 survivability mode 下提示 firmware flash。来源：https://docs.kernel.org/next/gpu/xe/xe_device.html

KMD 影响：生产 RAS 应分成三层：底层证据（heartbeat/ECC/fault/snapshot）→ KMD RAS policy（contain/recover/mark unhealthy）→ management contract（health state + recovery hint）。不要让上层运维通过解析 dmesg 猜 GPU 是否健康。
优先级：**health state schema 6–12 个月；底层 snapshot/heartbeat 现在。**

### Multi-GPU / P2P / Fabric
**本期无新的生产级方向变化。** `fabric_ext`（2026-07-28）仍是最新的长期 research signal：把 movement/ordering/ownership/link-health 作为跨 GPU/DPU/CXL fabric 的语义，但当前不应产品化。来源：https://arxiv.org/abs/2607.26335

KMD 影响：仍坚持 topology-first；先暴露稳定 identity/topology/P2P capability primitives，让上层 runtime 决策，之后才考虑 shared VM / fabric policy。
优先级：**topology/P2P 当前；fabric policy 长期。**

### Observability / Profiling
**本期最强信号来自 Xe GT Statistics 与现有跨层观测路线的结合。** Xe 用 per-CPU 64-bit counters 做高频 software telemetry，覆盖 SVM、TLB、migration、scheduler wait/reclaim；文档明确这样可以避免昂贵 atomic/cache-coherency traffic。来源：https://docs.kernel.org/next/gpu/xe/xe_gt_stats.html

结合 SysOM-AI 的 continuous cross-layer diagnosis（CPU stack + GPU kernel + NCCL + eBPF，报告 <0.4% overhead、80K+ GPU 部署）可以形成更完整路线：software counters 做 always-on low-cost health/benchmark，tracepoint/eBPF 做事件关联，PMU 做硬件瓶颈归因。来源：https://arxiv.org/abs/2603.29235

优先级：**software counters + object IDs 现在；PMU 6–12 个月。**

### Firmware / Control Plane
**本期首次纳入 Nova devinit 文档作为 control-plane lifecycle 信号。** Nova 描述 reset 后 FWSEC/GSP/PMU 等 firmware 阶段：devinit 负责 VRAM timing、power sequencing、clock/PLL、thermal 等初始化，host 等待 `GFW_BOOT` 后才继续；同一 devinit 序列也与 runtime suspend/resume 有关。来源：https://docs.kernel.org/next/gpu/nova/core/devinit.html

此外，nova-core 作为第一层 driver 继续明确为 firmware-version-independent API，服务 nova-drm 和未来 VFIO/vGPU 第二层 driver。来源：https://docs.kernel.org/next/gpu/nova/index.html 、https://docs.kernel.org/next/gpu/nova/core/guidelines.html

KMD 影响：自研 control plane 应显式定义 `RESET → SECURE_FW → DEVINIT → FW_READY → KMD_HANDSHAKE → SERVICE_READY` phase/generation，而不是只有一个“FW loaded”布尔值。
优先级：**现在设计。**

## E. 本期长期 Learning Resources 新增

本期只新增四类真正高价值资料：

1. Memory / Large Pages & Migration Granularity：**Intel Xe GT Statistics**。价值：提供可直接借鉴的 4K/64K/2M fault/migration/copy/bind/TLB measurement schema；注意它是 debugfs statistics，不是稳定 uAPI。
2. Observability / PMU：**Intel Xe GT Statistics**。这里学习目的不同：重点是低开销 per-CPU software counters 与 PMU/tracepoint 的职责边界，以及如何避免 high-frequency atomics。
3. RAS / Heartbeat & Hang Detection：**Intel Xe GPU Health Indicator / Device Wedging**。价值：把底层 RAS evidence 转成管理面可消费的 health state 和 recovery hint。
4. Firmware / FW-centric Services：**Nova Device Initialization (devinit)**。价值：建立 reset→secure firmware→devinit→host-ready→runtime PM 的完整生命周期直觉。

其余子方向本期没有发现足够高价值的新长期资料，保持原库不变。

## G. 本期重点 Feature 深挖 — GPU Memory Fault/Migration Measurement Contract

### 目标
在第一版 recoverable fault correctness 跑通的同时，建立后续优化不会推倒重来的可观测指标。

### Event/object IDs
每个 fault 至少关联：device_id、pid/tgid、pasid、vm_id、context_id、queue_id（可得时）、fault_id、reset_generation、vm_generation、VA、access type、page-size/migration-unit。

### Phase timestamps/counters
建议至少拆分：fault IRQ/packet received；work queued；process/mm/VM lookup；HMM/get-pages；migration prepare；DMA/copy start/end；GPU PTE bind；TLB invalidate start/end；revalidation；replay submitted/completed。

### Core metrics
- fault_count / valid-fault_count / fatal-fault-count
- fault latency histogram
- get_pages_us
- migration_count/us/bytes by 4K/64K/2M
- CPU→GPU and GPU→CPU copy time/bytes
- GPU bind time
- TLB invalidation count/time
- duplicate/concurrent fault count
- notifier-race retry count
- reset-generation abort count
- reclaim/eviction count/abort

### 3–6 月 deliverable
完成一个单 GPU pageable-memory scenario：fault→HMM→migration→PTE→TLB→replay，并有可重复 benchmark 能回答每个阶段耗时、失败点和 page-size 分布。实现 4K correctness，同时让数据结构/metrics 不把 4K 写死。

### 6–18 月
加入 batched 4K、64K/HW-native page、2M/compound experiment；再进入 oversubscription/eviction。用 measurement 选择 granularity，而不是先凭理论选 64K/2M。

### 1–2 年
将 counters 与 unified timeline/PMU 对接；实现 per-process/context memory attribution；多 GPU 时扩展为 per-device residency/migration view。

## H. VFIO / SR-IOV 条件

先确认 SR-IOV capability、VF BAR/MSI-X、VMID、queue/doorbell/interrupt partition、memory/engine partition、VF FLR、PF↔VF control path、IOMMU isolation。缺少这些时，不把 generic PCI SR-IOV enablement 包装成 Owner 项目。Xe configfs 的 `max_vfs` / pre-bind model 仍是很好的参考。

## I. Power / Performance

本期路线不变：measurement→lifetime correctness→DVFS/runtime PM。尤其关注 PM reference 和 memory reclaim/suspend 的交叉；所有活跃路径的 PM lifetime 必须能静态/运行时验证。Telemetry 应同时服务 Power 和 Observability。

## J. Reliability / RAS

本期建议把 RAS 架构明确成：Detect → Freeze Evidence → Diagnose/Classify → Health State → Contain/Recover → Restore → Clear/Update Health。`gpu_health` 不直接复制，而是借鉴“管理面稳定契约”的思想。

## K. Multi-GPU / P2P / Fabric

继续 topology-first。当前 feature 输出至少包括 stable logical/physical GPU identity、BDF/minor mapping、NUMA/root-port/switch graph、visibility/affinity、P2P capability matrix、failure reason（ACS/IOMMU/root-complex/no peer aperture 等）。共享 VM/UVM 在这些基础设施稳定后进入。

## L. Observability / PMU / eBPF

当前三层模型：
1. Always-on low-cost software counters；
2. Stable tracepoints/eBPF + object correlation；
3. Hardware PMU/perf/profiler sampling。

三层共用同一 object identity/timestamp model，避免 debug、profiling、RAS 各自发明 ID。

## M. Firmware / Control Plane

本期建议新增明确 phase machine：RESET_GENERATION_N → secure FW/devinit → FW boot-complete/GFW_BOOT → host handshake → version/capability negotiation → service ready；任何 FW restart/reset 递增 generation，旧 seq/request/completion 必须被拒绝或隔离，随后进行 resource/state reconciliation。

## N. Public Future Topic

继续跟踪：GPU SVM/drm_pagemap；Nova two-layer Rust KMD；Xe SR-IOV/configfs；device health/wedging；CXL Type-2 accelerator passthrough；gpu_ext/fabric_ext；Linux MM/IOMMU/PCIe/CXL/eBPF 变化。当前没有证据新增第 8 个 Owner。

## O. 8–10 人拆分

- Memory：GPUVM/Fault/Migration sub-owner + Leader 持有 architecture/policy。
- Virtualization：真实产品量足够时拆 Security/Confidential GPU。
- Observability：Trace/Telemetry/PMU；programmable policy 只在成熟后独立。
- Firmware：Protocol/Lifecycle/State 与 HW-management/FW scheduler 可在 workload 足够时拆分。
- RAS 继续独立于 Observability：前者拥有 failure semantics/recovery，后者提供 instrumentation substrate。

## P. Leader Memory 本期深挖主题

**Migration Granularity Measurement Matrix**。针对 4K、batched-4K、64K、2M 四种候选 granularity，逐项列出：fault rate、HMM/get-pages cost、DMA-map cost、copy setup/data cost、PTE update cost、TLB invalidation cost、internal fragmentation、false migration、CPU/GPU bounce、reclaim cost。目标不是证明“大页更快”，而是明确在什么 access pattern / pressure / hardware page-size 条件下哪一档最优。

## 本期核心结论

七个 Owner taxonomy 不变。最大的路线增强是：Memory 从“做 migration granularity”升级为“先建立粒度可比较的 measurement contract”；RAS 从“能 snapshot/reset”升级为“未来要有管理面 health/recovery contract”；Firmware 从“versioned messages”升级为完整 boot/reset phase & generation lifecycle。其余方向保持既有优先级，不以旧闻制造方向变化。
