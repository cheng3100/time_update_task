# GPU KMD Owner Direction — 2026-08-22 Weekly #2

## Executive summary
Seven-owner taxonomy remains unchanged. This run strengthens three cross-owner contracts: (1) RAS reset admission/generation as a reusable subsystem, informed by Tyr reset v4; (2) PF↔VF admin-channel architecture as the real virtualization control-plane work, informed by enic SR-IOV V2; (3) firmware-independent core capability/property services, informed by current Nova work. Memory remains the leader depth line with recoverable fault/HMM/migration/replay and measurement-first granularity work.

## D. Industry updates
### Memory
No new direction-level GPU SVM change in the short window. Linux 7.2 includes an AMDGPU PASID TLB-flush fix and TLB-invalidation semaphore work, reinforcing that TLB invalidation completion/ordering is correctness-critical rather than a minor tail step in migration/fault replay. Keep the existing measurement/race plan.

### Virtualization/Security
Cisco enic SR-IOV V2 v13 (2026-08-12) implements a direct PF↔VF admin channel with dedicated WQ/RQ/CQ resources, MSI-X and mailbox protocol. This is a durable cross-subsystem reference for GPU PF/VF control-plane design, while GPU implementation remains ASIC-capability-gated.

### Power/Performance
No high-value GPU-specific direction-level new item. Keep lifetime/measurement before governor.

### RAS
Tyr GPU reset v4 (2026-08-13) uses a dedicated reset workqueue, explicit pending/in-progress state and an SRCU-based gate to block/admit normal operations around reset. This strongly supports a reusable reset-gate/generation primitive after snapshot-before-reset.

### Multi-GPU
No new production-level direction change. Keep topology/P2P first and shared residency policy under Memory.

### Observability
Perf AUX kernel-consumer API RFC plus DAMON/ARM SPE integration show a general Linux direction where hardware-generated trace streams can be consumed by in-kernel observability frameworks. For GPU PMU/trace, retain perf-compatible event semantics and avoid a closed vendor-only stream if hardware permits.

### Firmware/Control Plane
Nova parameter-export v4 (2026-08-11) exposes basic GPU properties from nova-core to nova-drm and feeds a GPU-info ioctl, concretely showing a firmware/HW-independent core property service. Nova PRAMIN work also demonstrates typed lower-layer MMIO/window ownership.
