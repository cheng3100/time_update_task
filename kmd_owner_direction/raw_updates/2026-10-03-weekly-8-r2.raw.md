> 本版是 2026-10-03 Weekly #8 按新版深度标准重新生成的 R2。七个切入点 HLD 已扩展为 problem-first 16-section 结构。七个一级 Owner taxonomy 不变；从本版开始，周报由“摘要”升级为“原文事实 → 机制解释 → 自研 KMD 影响 → 可验证动作”，并为七个当前切入 feature 建立独立 HLD-like 页面。

## A. 本期最值得新增 / 增强的 Feature

### A1. P0 — Memory：Recoverable Fault 从 fault handler 升级为 SVM Range Recovery Service
XDC 2026 的 DRM SVM 总结把同步模型、range、native large-page、fault/non-fault execution 和未来 multi-device 放进同一条架构路线。对自研 KMD 的关键不是照搬 DRM SVM API，而是第一版即使只做 4K fault，也不要把 logical SVM range、CPU page、migration unit、GPU PTE unit、TLB invalidation unit 绑定成同一个粒度。

原文索引：
- XDC 2026 DRM SVM: https://indico.freedesktop.org/event/12/timetable/?view=standard
- Linux GPU SVM RFC: https://docs.kernel.org/gpu/rfc/index.html
HLD: /kmd_owner_direction/features/memory-recoverable-fault.html

### A2. P0/P1 — Multi-GPU：P2P Capability Matrix v2
PCI/P2PDMA 在 2026-10-01 演进到 v9，共 18 patches。v9 相比 v8 暂时移除 dma-buf patches 和 mlx5 per-mapping ATS declaration，把范围收敛到 P2PDMA routing。核心修正是：不能对整条路径和所有 TLP 给一个 P2P 答案；Request/Completion、Address Type、ACS Translation Blocking/Redirect、ATS 都会改变结果。

因此自研 KMD 的 P2P query 应从 bool 升级为 direction × TLP class × address type × ATS/ACS，并返回 DIRECT/REDIRECT/BLOCKED + reason。
原文：https://lwn.net/Articles/1098081/
HLD: /kmd_owner_direction/features/multi-p2p-matrix.html

### A3. P0/P1 — RAS：Device-I/O Admission Gate 成为跨 Owner contract
Xe v2 15-patch wedge isolation 系列针对典型 TOCTOU：线程先看到 device healthy，随后 recovery/wedge 开始，但线程已经越过检查并继续 MMIO/DMA/FW access。方案是让 hardware user 在 state check 前进入 DRM SRCU gate；recovery 先 publish blocked，再 drain 已进入 reader，最后隔离设备。

VFIO PCI error recovery v2 也采用 access blocking + SRCU drain，说明 admission/drain 是通用 device lifecycle primitive。

- https://www.mail-archive.com/dri-devel%40lists.freedesktop.org/msg638180.html
- https://lwn.net/Articles/1097488/
HLD: /kmd_owner_direction/features/ras-recovery.html

### A4. P1 — Firmware：Versioned ABI 不等于散落的 fw_version 分支
Nova r000 GSP v3 是 33-patch 系列，把 nova-core 从 r570 GSP ABI 迁移到 r615+ 共享 ABI。系列在最终切换前保持旧 firmware 可启动，先建立兼容抽象，再切 provider。自研 control plane 应对应拆为 Transport、Message Envelope、Versioned Service ABI，并集中 capability/generation/restart translation。

- https://patchew.org/linux/20260918010719.1176945-1-jhubbard%40nvidia.com/
- https://dri.freedesktop.org/docs/drm/gpu/nova/index.html
HLD: /kmd_owner_direction/features/fw-versioned-protocol.html

### A5. P1 — Virtualization：PCI Error Recovery 成为 VFIO lifecycle 显式状态
VFIO PCI error recovery RFC v2 共 16 patches。旧 vfio-pci 在 error_detected() 只 signal eventfd，却没有 slot_reset()/resume()，userspace 不知道 host recovery 是否完成或 device 是否 reset。v2 增加 opt-in host recovery、access blocking、state restore 与 recovery status notification。
原文：https://lwn.net/Articles/1097488/

## D. Industry Updates — 原文级分析

### D1 Memory
XDC 2026 AMD 的 DRM SVM 报告指出 KFD SVM 依赖 mmap read/write locks，driver 与 system MM 同步耦合较重；DRM SVM 采用更简化同步模型，并设计 native large-page、memory attribute 与 physical layer 分离、最高 2MB granularity 的 range model，同时展示 XNACK-on fault-driven 与 XNACK-off non-fault-driven，并讨论 single-device 向 multi-device 演进。

可抽取原则：logical range identity 独立于 physical residency 和 PTE representation。建议实验：2MB logical range + 4K GPU PTE + 64K migration batch，验证 range identity 不需要随实现粒度变化。
优先级：P0 architecture compatibility。
原文：https://indico.freedesktop.org/event/12/timetable/?view=standard

### D2 Virtualization / Security
2026-09-29 VFIO PCI error recovery RFC v2 共 16 patches。旧 vfio-pci 缺少 slot_reset()/resume()，error eventfd 只能表达“发生错误”，不能表达 recovery completion/reset result。v2 恢复期间阻止 device access，用 SRCU drain 已有 access，host 恢复 PCI device state，再向 userspace 报告 recovery state。

GPU PF/VF 应抽取三个 contract：PF/host 拥有物理 recovery；VF/VMM 有明确 recovery-state notification；error window 内 device access 被 admission gate 封闭。建议做 VF workload + injected AER，验证 submission/MMIO/doorbell/DMA/FW admin request 的 recovery-window 语义。
优先级：P1；ASIC SR-IOV ready 时升 P0/P1。
原文：https://lwn.net/Articles/1097488/

### D3 Power / Performance
本期无足以改变路线的 GPU-specific 高价值新增。继续以 Linux runtime PM 与 Xe PM 为 baseline。值得保留的工程案例是 Xe page-fault worker 与 runtime PM race：VM teardown 异步 drop PM ref 后，queued stale fault 仍可能 wake 并向已 suspend GuC 发 ack。这说明 software object/workqueue lifetime 与 device active lifetime 必须显式耦合。

建议测试 stale fault/FW completion/telemetry worker × runtime suspend；记录 PM ref reason、quiesce latency、resume cause。
优先级：P1 correctness。
原文：
- https://docs.kernel.org/power/runtime_pm.html
- https://kernel.googlesource.com/pub/scm/linux/kernel/git/kdave/linux/+/20fce5b34b21a995839743b4917a1edd2fd503ba

### D4 Reliability / Recovery / RAS
Xe isolate wedged devices v2 共 15 patches。核心不是 reset 本身，而是 state-check TOCTOU。hardware access 在 DRM SRCU critical section 内检查 state；recovery block new access、signal pending fences、drain reader，再停 interrupt/DMA。recoverable PCI error 与 permanent wedge 保持不同 terminal semantics。

设计原则：Gate != Generation != Health State。Gate 是同步 primitive；generation 过滤 stale async result；health 是对上层公布状态。建议 fault injection：fault worker×reset、FW request×reset、VRAM mmap×wedge、remove×background worker、AER×submission。
优先级：P0/P1。
原文：
- https://www.mail-archive.com/dri-devel%40lists.freedesktop.org/msg638225.html
- https://www.mail-archive.com/dri-devel%40lists.freedesktop.org/msg638180.html

### D5 Multi-GPU / P2P / Fabric
2026-10-01 PCI/P2PDMA v9 共 18 patches。v9 暂时移除 dma-buf 和 mlx5 per-mapping ATS patch，集中完成 P2PDMA routing。三类 ACS control 依赖 client 选择的 TLP attributes，而非纯 topology：Translation Blocking 与 Direct Translated P2P 取决于 Request Address Type；Completion Redirect 对 Relaxed Ordering Completion 有不同语义；ATS enabled client 默认视为 translated，除非以后 driver 能声明 per-mapping ATS。

因此 capability matrix 至少需要 source、destination、direction、TLP class、address type、ATS mode、ACS path，并保留具体阻断 port/reason。建议覆盖 same/nested switch、A→B/B→A、ATS/IOMMU on/off、ACS Translation Blocking/Redirect。
优先级：P0/P1。
原文：https://lwn.net/Articles/1098081/

### D6 Observability / Profiling
AMDGPU profiler/SPM UAPI 仍处于架构 review。12-patch 系列增加 DRM_AMDGPU_PROFILER ioctl 与 GET_VER/SPM operation，header 先定义 operation/buffer layout，但 ioctl 等 implementation ready 后才注册。长期价值是提醒我们：先定义 profiler resource ownership/lifetime，再冻结 UAPI。

自研 profiler_session 至少包含 owner、partition、PID/PASID、VM/context、counter set、buffer、generation、refcount、reset/unplug behavior。最终可选择 perf_event、vendor ioctl、UMD direct 或 FW service。
优先级：P1 architecture。
原文：https://www.mail-archive.com/amd-gfx%40lists.freedesktop.org/msg151914.html

### D7 Firmware / Control Plane
Nova r000 GSP v3 共 33 patches，把 nova-core 从 r570 ABI 迁移到 r615+ 共用 ABI；最终切换前仍保持 r570 可启动，体现“先建立兼容层，再切 provider”。Nova 架构又明确 nova-core 是 first-level driver，封装 HW/FW interface，向 nova-drm 与未来 vGPU/VFIO second-level driver 提供公共 base。

自研 KMD 应让 Memory/RAS/Power/Virtualization 消费稳定 service API，而不是理解 raw FW ABI。建议用两个 mock FW version 验证同一 service API；restart 后 re-handshake；注入旧 generation completion；transport integrity failure 时不解析 upper RPC。
优先级：P1。
原文：
- https://patchew.org/linux/20260918010719.1176945-1-jhubbard%40nvidia.com/
- https://dri.freedesktop.org/docs/drm/gpu/nova/index.html

## G. 重点切入 Feature：Recoverable Fault / SVM Range Recovery Service
GPUVM 回答“GPU VA 怎样翻译”；recoverable fault 回答“翻译暂时不存在时，怎样恢复地址并继续原 workload”。最小模型应分为 svm_range、per-device range state、fault work、migration object、PTE/TLB operation。

第一版至少区分 mmu_notifier_seq、vm_generation、context_generation、recovery_generation。只有 MM/notifier、range/VM/context/recovery generation 都有效，migration/PTE/TLB ordering 完成，FW replay service ready 且 device I/O admitted 时才能 replay。

3–6 月：0–1 月对象/锁/generation/fault schema；1–2 月 fault→HMM→PTE/TLB→replay；2–3 月 VRAM migration；3–4 月 munmap/mprotect/exit/context destroy/reset race；4–6 月 pressure/fault injection/measurement。
1–2 年：large page、oversubscription/reclaim、migration policy、multi-device、multi-GPU UVM、NUMA/tiered/CXL、ATS/PRI/SVA。

## H. VFIO / SR-IOV
重点从 provisioning 扩展到 recovery ownership。第一阶段 capability matrix 至少包含 VF count、VMID/queue/doorbell/IRQ/memory partition、ATS/PASID/IOMMU、FLR scope、AER behavior、FW admin-channel capability。没有硬件支持则只做 assessment，不制造伪项目。

## I. Power
第一版 deliverable 是 measurement + lifetime：per-engine busy/idle、utilization window、frequency residency、PM ref reason、suspend/resume latency、quiesce timeout。没有这些数据不做复杂 governor。

## J. RAS
能力闭环固定：Detect → Freeze Evidence → Publish Blocked → Close Admission → Drain → Advance Generation → Reset/Isolate → Reconcile → Validate → Publish Health → Reopen。第一版先做 device-wide semantics，再考虑 engine/context-level recovery。

## K. Multi-GPU
当前 feature 正式定义为 Topology + Direction + TLP Class + ATS/ACS + Capability + Reason。Memory 决定 residency/migration；Multi-GPU 提供 peer transaction reachability 和 fabric lifecycle 事实。

## L. Observability
第一阶段 stable identity + trace/eBPF；PMU/SPM 后接入同一 timeline。reset_generation 必须是 correlation key，避免 reset 前后的同名 queue/job 被错误串联。

## M. Firmware
HLD 采用三层：Service（Memory/PM/Reset/Scheduler）→ Message Envelope（version/type/seq/status/generation）→ Transport（ring/slot/index/integrity/doorbell）→ MHU/shared memory。Transport integrity 失败时不得继续信任 upper message fields。

## P. Leader Memory 深挖：不要把“页”当成唯一架构粒度
SVM Range、CPU page、migration unit、GPU PTE、TLB invalidate unit 是五个不同概念。一个 2MB logical SVM range 可以由 4K CPU pages 构成，当前用 64K batch migration、4K GPU PTE，而 TLB invalidate 覆盖更大范围；未来 GPU 支持 2MB PTE 后，不应该改变 SVM range identity。

第一版数据结构因此应是 range → per-device state → residency/migration → PTE/TLB representation，而不是 fault VA → struct page → GPU PTE 的一对一链条。

另一个必须进入 HLD 的硬件问题是 fault-resolution path 是否与 faulting traffic 共享稀缺 translation/MSHR 资源。如果 fault 已占满 L1 TLB MSHR，而 DTE 用于搬页或更新页表的 PA transaction 仍必须占同一 MSHR，就可能形成“解 fault 的路径被 fault 本身堵死”的循环依赖。硬件评审必须明确 PA/bypass transaction 是否需要 translation miss state、是否有 reserved MSHR/escape path、page-table update/DMA 是否能走独立通道。

## 本期结论
新版周报的验收标准变成四层闭环：原文事实 → 机制解释 → 自研 KMD 设计原则 → 可验证 feature/HLD。七个 Owner 不变。最重要的三件事仍是：Memory 把 recoverable fault 做成 range-based recovery service；RAS 把 admission/generation/reconciliation 做成跨 Owner contract；Multi-GPU 把 P2P 从 topology bool 升级为 direction/TLP/ATS/ACS-aware matrix。

从本期起，七个当前切入点均有独立 HLD-like 页面，并在后续周报中增量维护，而不是每周重新写一段概括。

## R2 HLD 深化说明
R2 不改变七个 Owner taxonomy 和本期技术判断，而是把“当前切入点”从周报中的一句 feature 名称升级为可独立阅读的设计入口。七个 HLD 统一补齐：主题定义、背景/栈位置、实际问题、典型场景、核心对象、端到端流、跨层边界、生命周期/状态机、correctness/race/lifetime/performance 难点、failure/debug、最小闭环、3–6 月、1–2 年、Cross-Owner、upstream/vendor 索引、hardware/open-question gates。

特别是 Memory HLD 新增了 fault-resolution escape-path 问题：如果 faulting traffic 占满 translation MSHR，而 DTE 的 PA 搬页/页表更新仍依赖同一 MSHR，可能形成循环等待；因此硬件 capability review 必须回答 PA/bypass transaction 是否消耗 translation miss state、是否存在 reserved MSHR/escape path，以及 page-table update/DMA 是否有独立通道。

Multi-GPU HLD 把 PCI/P2PDMA v9 的原文结论固化为 capability schema：source/destination + direction + TLP class + Address Type + ATS/IOMMU + ACS decision + generation + reason，而不是一个 topology boolean。

RAS HLD 把 Gate / Generation / Health State / Reconciliation 四个概念分开：Gate 管“现在能不能碰硬件”；Generation 管“异步结果是否属于当前 world”；Health State 管对外可见状态；Reconciliation 管 reset 后重建哪些 SW/FW/HW state。

从下一期起，周报 C 节每个切入点必须链接稳定 HLD，并只写“本周 HLD 新增/改变了什么”；主题本身的完整解释沉淀在 HLD 页面，不再每周重复压缩成一句话。
