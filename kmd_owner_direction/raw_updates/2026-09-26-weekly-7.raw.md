# GPU KMD Owner Direction 周度更新 — 2026-09-26

本期保持七个一级 Owner taxonomy 不变。最值得吸收的新信号来自 Xe 的 **device-I/O gate**：9 月 22 日 v2 15-patch 系列把 PCI error recovery、permanent wedge、page fault、SVM、VM rebind、GuC、VRAM CPU mapping、PM 与 userspace notification 放进同一个“先封闭硬件访问、drain 已进入访问者、再隔离/恢复”的生命周期。它与我们前几期的 Recovery Admission / Generation / Reconciliation 高度一致，但进一步说明这个 gate 不是 RAS 私有 helper，而应成为所有可能触碰 HW 的 KMD 路径共同消费的底层 contract。

## A. 本期最值得新增/增强的 Feature

1. **P0 — Device I/O Admission Gate + Fault/Migration Drain Contract（RAS × Memory）**：把 fault、migration、rebind、FW request、MMIO/doorbell 等硬件访问统一纳入可关闭、可 drain 的 admission domain。
2. **P0 — Recoverable Fault + HMM + Migration + Replay**：主线不变；新增“recovery/wedge 开始后，queued fault 必须丢弃、in-flight fault 必须被 gate drain”的明确 invariant。
3. **P1 — Lifecycle Resource Pairing（RAS × Power × Virtualization）**：init/suspend/resume/fini/VF 分支上的 IRQ、FW service、PM reference 等资源必须成对，不能把 acquire/release 分散在不同 lifecycle 层。
4. **P1 — Compute SPM / Profiler Ownership Boundary（Observability）**：AMD 新 profiler/SPM UAPI 讨论出现强烈争议，核心不是 ioctl 形式，而是 compute SPM 应由 KMD、UMD 还是 MES/FW 管理。
5. **P1 — Restore-State Validation（Virtualization/Security）**：CRIU/迁移恢复输入中的 queue/resource ID 必须做 capability + bounds + generation 验证，不能把“恢复数据”当可信内部状态。

## B. 七个 Owner + 子方向雷达

**Memory**：Fault/HMM correctness P0 → migration P0/P1 → reclaim/eviction P1 → oversubscription/QoS P1/P2。新增重点是 fault/migration 与 device-I/O gate 的组合正确性。

**Virtualization/Security**：PF/VF provisioning → capability matrix → FLR/recovery → serialize/restore → live migration。恢复输入 validation 提升优先级。

**Power/Performance**：utilization → PM lifetime/quiesce → runtime PM → DVFS。Xe PME/C6/D3 工作继续证明“进入低功耗”是跨 PCI/GT/display/reclaim 的 transaction。

**RAS**：Detect → Evidence → Admission Gate → Drain → Scope/Generation → Reset → Reconcile → Restore → Validate → Health。本期 Admission Gate 从概念变成最值得直接实现的 feature。

**Multi-GPU**：identity → topology → directional P2P → peer mapping/DMA → fabric health → shared VM。无方向级新增。

**Observability**：stable ID → counters → trace/eBPF → structured RAS → PMU/SPM → unified timeline。本期重点是 profiling control-plane ownership，而非急着冻结新 uAPI。

**Firmware**：versioned ABI → async/sequence → capability → generation/readiness → shared memory → restart/reconcile。新增要求：所有 FW/HW access 都必须服从 device-I/O admission domain。

## C. 每个 Owner 当前切入点

Memory：Recoverable Fault + HMM + Migration + Replay，并把 I/O gate、notifier、teardown、reset generation 纳入第一版 correctness。
Virtualization：有 SR-IOV 则 PF/VF provisioning + resource capability/restore validation；否则 capability assessment。
Power：utilization + PM quiesce matrix。
RAS：Device I/O Admission Gate + frozen snapshot + reset reconciliation。
Multi-GPU：stable identity + topology + directional P2P matrix。
Observability：stable event/object/error ID + eBPF；评估 compute SPM 的 ownership。
Firmware：versioned async protocol + shared-memory ownership + generation/readiness + gate-aware request lifecycle。

## D. Industry Updates

### D1 Memory
**2026-09-22 / Intel Xe / Isolate wedged devices v2**：page-fault queue 在 I/O blocked 后直接丢弃 queued fault；正在执行的 fault 持有 common SRCU I/O gate，wedge isolation 等待其退出；VM/SVM migration、pagemap population、rebind 同样被 gate 覆盖。来源：https://www.mail-archive.com/dri-devel%40lists.freedesktop.org/msg638225.html 。对自研 KMD：fault worker 不能只检查一次 reset flag，必须把“检查状态 + 实际 HW/PTE/migration access”放在同一 admission critical section。**优先级 P0。**

### D2 Virtualization / Security
**2026-09-24 / AMDKFD CRIU / SDMA queue restore bounds**：restore_sdma_id 来自恢复数据，此前未检查是否小于最大 queue 数。来源：https://app.opencve.io/cve/CVE-2026-97497 。对自研 KMD：未来 VF/live migration/CRIU 的 restore blob 必须视为外部输入；resource ID、queue type、size、capability、generation 全部 validate 后才能映射到真实 HW resource。**优先级 P1。**

### D3 Power / Performance
**2026-09-21 可见于 linux-next / Intel Xe PME + C6-before-D3**：Xe 的 runtime suspend 同时合并 PME wakeup 与进入 D3 前等待 GT C6；PME enable 失败还需要 rollback，相关路径与 reclaim lock ordering 有交互。来源：https://lists.openwall.net/linux-kernel/2026/09/21/1536 。对自研 KMD：runtime suspend 应被建模为 transaction：close users → drain → verify engine idle → arm wake source → enter low power；任一步失败都可 rollback。**优先级 P1。**

### D4 Reliability / RAS
**2026-09-22 / Intel Xe / common device-I/O gate**：permanent wedge 先 publish blocked state、signal fences、drain hardware users，再停 IRQ/bus mastering、invalidate VRAM CPU mappings、拒绝新 VRAM allocation，最后通知 userspace；AER temporary recovery 与 permanent wedge 使用不同错误语义。来源：https://www.mail-archive.com/dri-devel%40lists.freedesktop.org/msg638225.html 。这是本期最高价值更新。**优先级 P0。**

**2026-09-24 / AMDGPU RAS IRQ lifecycle**：cp_ecc_error_irq 的 get/put 曾跨 late_init、hw_fini 且 VF 条件不对称；修复增加 ras_suspend，使 acquire/release 位于同一 RAS lifecycle，并用 active flag 处理 suspend→unload。来源：https://lists.openwall.net/linux-kernel/2026/08/31/2497 。对自研 KMD：每个 RAS/IRQ/FW resource 都应有 owner + lifecycle state，而不是 teardown 时查询“现在看起来是否 enabled”。**优先级 P1。**

### D5 Multi-GPU / P2P / Fabric
**本期无高价值方向级新增。** 保持 topology/control-first。Xe wedge 对 VRAM mapping 的失效进一步提示未来 peer mapping 也必须绑定 device/fabric generation，但目前只作为 architecture reserve。

### D6 Observability / Profiling
**2026-09-21~23 / AMDGPU compute SPM profiler UAPI RFC**：12-patch 系列尝试加入 AMDGPU_PROFILER ioctl/SPM buffer；review 明确质疑为何 compute SPM 必须进入 KMD uAPI，讨论指出 graphics SPM 已可由 userspace 使用，而 ROCm user-mode queue 的 VMID 由 MES 分配，使 compute SPM ownership 与未来 KFD/KGD/MES unification 纠缠。来源：https://www.mail-archive.com/amd-gfx%40lists.freedesktop.org/msg151914.html 与 https://www.mail-archive.com/amd-gfx%40lists.freedesktop.org/msg151941.html 。对自研 KMD：先定义“谁拥有 counter programming、VMID attribution、exclusive acquire、buffer lifetime”，再决定 ioctl/perf_event/FW service。**优先级 P1 架构，暂不冻结 uAPI。**

### D7 Firmware / Control Plane
本期没有独立于前述 I/O-gate/SPM ownership 的新方向级 FW patchset。最重要影响是：FW request/ring/shared-memory access 也必须进入 device-I/O gate；recovery 开始后旧 generation request 要停止进入 HW，in-flight request 要 drain/cancel/reconcile。**本期无额外高价值新增。**

## E. 长期 Learning Resources 本期新增/替换

本期建议只新增一条：**Xe “Isolate wedged devices from hardware access” v2**，归入 RAS 的 Recovery/Reset 与 Memory Fault/Replay 两个资料索引中的 Implementation/Practice 交叉引用。它值得长期留存，因为这是一个完整展示 common SRCU admission gate 如何同时覆盖 fault、SVM、VM、GuC、VRAM mapping、IRQ、PCI/AER、PM 和 userspace notification 的 production-scale case study。学习重点是 gate scope、drain ordering、temporary AER 与 permanent wedge 的语义差异；注意它当前仍是 patch series，不应照搬具体 API。

## G. 重点 Feature：Device I/O Admission Gate（3–6 月 / 1–2 年）

目标不是再加一个 `bool resetting`，而是建立：
```
access_begin(class)
  → admission check
  → enter reader domain
  → revalidate state
  → hardware access
  → access_end()

recovery/wedge
  → publish BLOCKED
  → reject new readers
  → drain existing readers
  → snapshot/reset/isolate
```

**0–1 月**：枚举所有 hardware-touching path：MMIO、doorbell、FW mailbox/ring、fault ack、PTE/TLB、migration DMA、IRQ worker、telemetry、VRAM CPU fault、reset worker。定义哪些必须进入 gate。

**1–2 月**：实现 device-wide gate，至少支持 RUNNING / QUIESCING / RECOVERING / PERM_WEDGED；新访问返回明确错误，禁止 check-then-access race。

**2–3 月**：接入 Memory fault/migration/rebind。queued fault 在 blocked 后丢弃；in-flight fault 必须在 gate 内完成到 safe point，recovery drain 后才能 reset。

**3–4 月**：接入 FW async request、IRQ/telemetry、PM。明确哪些路径允许在 QUIESCING 阶段运行（例如 crash snapshot），哪些必须拒绝。

**4–6 月**：fault injection：fault×reset、migration×AER、FW request×wedge、mmap VRAM×wedge、suspend×recovery、remove×RCU callback。验证 drain 无死锁且无 post-block HW access。

**1–2 年**：从 device-wide gate 演进为 scope-aware admission：DEVICE / ENGINE / FW SERVICE / FABRIC CONNECTION；但避免一开始就做复杂层级锁。

## H. VFIO / SR-IOV

继续 hardware-gated。新增明确原则：restore/migration payload 是不可信输入。每个 logical resource ID 必须经过 bounds、type、capability、ownership、generation 验证后才能恢复。AMDKFD restore_sdma_id 的 bounds bug 是很直接的反例。

## I. Power

PM Owner 本期重点不是新 governor，而是把 runtime suspend 变成可回滚 transaction：quiesce users → drain I/O gate → engine idle/C6 → arm PME/wakeup → D-state；失败按反方向 rollback。PM reference 必须覆盖真实硬件访问区间，而不是只覆盖入口函数。

## J. RAS

RAS 第一阶段闭环更新为：
```
Detect → Freeze Evidence → Publish Blocked
→ Close Admission → Drain I/O
→ Select Scope → Advance Generation
→ Reset/Isolate → Reconcile → Validate
→ Health Event → Reopen
```
其中 Admission Gate 是本期最高优先级；IRQ lifecycle 案例说明资源 acquire/release 也必须纳入同一生命周期模型。

## K. Multi-GPU

本期路线不变。预留 `fabric_connection_generation` 和 peer mapping invalidation：当某 GPU permanently wedged 或 link reset 时，远端不能继续持有旧 peer mapping。暂不提前做 fabric data path。

## L. Observability

SPM 讨论说明 profiling 的核心问题是 ownership：counter programming、exclusive acquire、VMID/PASID attribution、buffer ownership、FW/MES cooperation。建议当前先用 stable object ID + software counters + eBPF 建统一 timeline；HW SPM/PMU 接入时优先复用 identity，而不是先冻结私有 ioctl。

## M. Firmware

所有 FW command/event transport 增加 gate contract：发送前进入 gate；request 记录 fw_generation + recovery_generation；reset/wedge 阻止新 request；旧 completion 在 generation 不匹配时丢弃。Crash-log/snapshot service 可以被定义为 QUIESCING 阶段的例外 reader，但必须显式列出。

## N. Future Topic

重点跟踪四项：Xe common device-I/O gate 是否进入主线并沉淀 DRM common helper；AMDGPU compute SPM 最终选择 KMD uAPI、userspace 还是 MES/FW 路径；DRM_RAS 是否继续扩 health/recovery common semantics；XDC 2026 Tyr upstreaming 分享（9 月 30 日）将展示 Rust DRM GPUVM + firmware/MCU boot 的组合方式，值得下期跟踪，但本期尚未发生，不当作 Industry Update。

## O. 8–10 人拆分

Memory 拆 GPUVM/TLB、Fault/HMM/Migration、Residency/Reclaim/QoS；RAS 拆 Evidence/Health 与 Recovery/Admission/Reconcile；Firmware 拆 Protocol/Lifecycle 与 FW-managed Services；Observability 拆 Trace/eBPF/Schema 与 PMU/Profiling；Virtualization 在真实 SR-IOV 产品需求后拆 Provisioning/Isolation 与 Migration/Recovery/Security。一级 Owner 仍不增加。

## P. Leader Memory 深挖：Fault/Migration × Device-I/O Gate

本期最值得深挖的 race 是：
```
GPU fault queued
→ recovery publishes BLOCKED
→ old fault worker wakes
→ HMM succeeds
→ migration DMA / PTE update ?
```
正确设计不能靠 worker 入口的一次 `if (resetting)`。入口检查与后续 HW access 之间仍有窗口。更稳妥的模型是 fault worker 在真正开始处理前进入 I/O gate，并持有到最后一个可能触碰 HW/FW 的动作结束；recovery 先关闭 admission，再等待 reader drain。

同时必须区分四种失效来源：`mmu_notifier_seq` 处理 CPU MM 变化；`vm_generation` 处理 GPU VA mapping 生命周期；`context_generation` 处理 context/queue teardown；`recovery_generation` 处理 GPU/FW world replacement。I/O gate 解决“此刻还能不能碰硬件”，generation 解决“我手里的异步工作是否仍属于当前世界”，二者不能互相替代。

最终 replay 条件应接近：MM/notifier valid + VM/context generation valid + recovery generation unchanged + device I/O admitted + PTE publish complete + TLB ordering complete + FW service ready。这个组合正是 Memory Owner 从“能处理 page fault”走向系统级 UVM correctness 的关键。

## 本期结论

七个 Owner 不变。本期最重要的架构升级是把此前 RAS 的 Reset Gate 正式泛化为 **Device I/O Admission Gate**，并让 Memory fault/migration、Firmware async、Power PM、VRAM mapping、IRQ/telemetry 共同消费。第二个值得跟踪的是 AMD compute SPM 争论：它提醒我们 profiling 首先是 ownership/attribution/control-plane 问题，其次才是 ioctl 设计。
