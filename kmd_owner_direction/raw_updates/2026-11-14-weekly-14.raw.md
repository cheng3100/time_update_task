# GPU KMD 七大 Owner 技术路线周报

**Weekly #14 · 2026-11-14 · 研究窗口：2026-11-07—2026-11-13**

本期最值得关注的变化集中在四条线上：第一，AMDGPU 的 TLB invalidation / BO lifetime 修复从 v2 继续演进到 v3，并已经进入 7.4 fixes pull，进一步确认“PTE 更新完成 ≠ TLB 已失效 ≠ BO 可释放”；第二，VFIO 新增 7-patch P2P DMA selftest RFC，把 RAM↔BAR、BAR↔BAR、iommufd dma-buf revocation 等场景变成可自动验证的测试矩阵；第三，AMDGPU GFX user queue recovery 继续推进 engine soft reset，明确 user queue hang 不一定存在 guilty kernel ring；第四，SPM VMID 更新再次回到 ring emission，说明 profiling/PMU 状态在 GFXOFF/reset/IB 路径中的硬件可见性必须由显式时序保证。

## A. 本期 5 个重点 Feature

1. **P0 Memory：TLB invalidation completion → BO/page lifetime contract**  
   AMDGPU v3 明确把最后一次 TLB invalidate fence 纳入 BO reservation，避免 user queue 通过 stale translation 访问已经释放/复用的物理内存。对自研 KMD，应把 PTE publish、TLB issue、TLB completion、outstanding access drain、BO reusable 拆成不同阶段。

2. **P1 Multi-GPU / Virtualization：VFIO P2P DMA selftest matrix**  
   11 月 11 日的 VFIO RFC 7-patch 系列把 target BAR 映射进 IOMMU，并覆盖 RAM→BAR、BAR→RAM、BAR→BAR、roundtrip 以及 iommufd dma-buf revoke。它非常适合直接转化成自研 GPU P2P/peer-memory validation plan。

3. **P0/P1 RAS：UserQ → engine soft reset escalation**  
   AMDGPU v4 engine reset 系列明确：当 user queue reset 和 pipe reset 都失败时，可以升级到 gfx engine soft reset，再失败才 full reset；而 user queue 不一定有 guilty kernel ring，所以 reset API 应显式携带 device、scope、queue/context identity，而不是依赖 ring 推导。

4. **P1 Observability：SPM VMID update ring ordering**  
   11 月 12–13 日 SPM 修复把 VMID update 恢复为 ring emission，因为单纯 MMIO 路径在 gfx11 CI 中出现 flaky。说明 profiling state 不是“写寄存器即可”，必须考虑 engine ordering、GFXOFF、IB execution 与 reset generation。

5. **P0 Architecture：AMDGPU DRM SVM v10 继续 review**  
   11 月 11 日 upstream 继续推动基于 DRM GPUSVM/drm_pagemap 的 SVM v10/22 review。长期信号不变：HMM、page migration、mmu_notifier、GPUVM、eviction locking 正在向共享 DRM 基础设施收敛。

## D. 七 Owner Industry Updates

### D1. Memory/UVM — TLB flush completion 与 BO lifetime

原文：
- https://mail-archive.com/amd-gfx%40lists.freedesktop.org/msg155265.html
- https://mail-archive.com/amd-gfx%40lists.freedesktop.org/msg155717.html

AMDGPU v3 继续修复 GEM close 时 BO 可能早于历史 TLB invalidate completion 被释放的问题。v3 的变化是额外 fence slot 在锁内预留，不再依赖后续 helper 的隐式 reservation 行为。11 月 12 日的 drm-fixes-7.4 pull 已包含 TLB invalidation fence handling 修复，说明这不是理论讨论，而是现实 correctness bug。

对自研 KMD，建议把 BO/page lifetime 写成：

```text
GPUVA unmap
→ PTE update visible
→ TLB invalidate issued
→ TLB invalidate completed
→ outstanding access drained
→ BO/page reusable
```

验证：人为延迟 TLB completion，同时并发 unmap、close/free、重新分配同一物理页，检查旧 user queue translation 是否还能访问新对象。

### D2. Virtualization/Security — VFIO P2P DMA selftest RFC

原文：
- https://go.mail-archive.com/dri-devel%40lists.freedesktop.org/msg653091.html
- https://go.mail-archive.com/dri-devel%40lists.freedesktop.org/msg653096.html

11 月 11 日 7-patch RFC 引入 VFIO P2P DMA selftest。核心不是新增 GPU 功能，而是把 peer BAR 映射进 IOMMU 后的行为变成标准化自动测试。type1/type1v2 使用 VFIO_IOMMU_MAP_DMA；iommufd 路径使用 VFIO_DEVICE_FEATURE_DMA_BUF + IOMMU_IOAS_MAP_FILE，并验证 PCI_COMMAND_MEMORY 清除后的 revocation。

设计原则：**“拓扑上可达”与“映射生命周期正确”必须分别验证。**

### D3. Power/Performance

本周没有足够高价值的 GPU-specific 新方向。继续保持：
measurement/lifetime correctness → utilization telemetry → DVFS → runtime PM。不要用低质量新闻填空。

### D4. Reliability/Recovery/RAS — Engine reset escalation

原文：
- https://mid.mail-archive.com/amd-gfx%40lists.freedesktop.org/msg155234.html

AMDGPU v4/13 继续把 gfx user queue recovery 从 queue/pipe reset 扩展到 gfx engine soft reset。关键点是 user queue hang 不一定有 guilty kernel ring，因此 reset path 显式传 device + ring type，并允许 guilty ring 为空。

自研建议的 recovery ladder：
```text
queue abort/reset
→ pipe reset
→ engine soft reset
→ partial IP reset
→ full GPU reset
```

每一级都要有 admission gate、snapshot、generation、restore/reconcile 和升级条件。

### D5. Multi-GPU/P2P/Fabric — P2P verification 从 capability 走向 executable test

VFIO RFC 让 P2P matrix 不再只是静态 query。建议自研 KMD 在 capability matrix 之后直接接 executable probe：

- RAM→peer BAR write
- peer BAR→RAM read
- BAR→BAR copy
- roundtrip data integrity
- IOMMU identity/remap 两种模式
- mapping revoke 后 stale DMA 必须失败
- A→B 与 B→A 分开测试

### D6. Observability/Profiling — SPM VMID update 必须服从 engine ordering

原文：
- https://mail-archive.com/amd-gfx%40lists.freedesktop.org/msg155737.html
- https://mail-archive.com/amd-gfx%40lists.freedesktop.org/msg155811.html

11 月 12–13 日修复表明，SPM VMID update 只走 MMIO 会导致 gfx11 CI flaky，因此对有 GFXOFF 的芯片恢复 ring emission。对自研 KMD，PMU/SPM/profiler session 需要显式区分 desired configuration、submitted configuration、hardware-applied generation，并在 reset/GFXOFF/resume 后 reconcile。

### D7. Firmware/Control Plane

本周没有新的、足以改变 versioned async protocol / capability / restart-generation 路线的高价值 upstream 变化。保持现有 HLD，不制造更新。

## G. 本期重点 Feature 深挖：TLB Completion → Object Lifetime

3–6 月目标：
- 把 GPUVA unmap、PTE publish、TLB issue/completion、DMA/access drain、object free 建成显式状态；
- 对每个 VM/BO 保存 last invalidate generation/fence；

- multi-GPU per-device TLB generation；
- ATS/PRI/SVA translation cache；

## H. VFIO / SR-IOV

本周重点不是 SR-IOV enable API，而是 VFIO P2P selftest 说明 virtualization owner 必须把 IOMMU mapping、BAR lifetime、revocation 和 peer access 纳入验证。SR-IOV 仍由 ASIC/FW capability gate。

## I. Power

无方向变化。保持 utilization accounting → runtime PM/DVFS。未来与 Observability 共用 PMU/SPM telemetry，但 ownership 不合并。

## J. RAS

新增明确的 engine-reset escalation contract。Recovery 不应只有“full reset”一个按钮，而应支持 scope、guilty object 可选、generation 和失败升级。

## K. Multi-GPU

P2P capability matrix 后增加 executable verification。静态 topology/ACS/ATS/IOMMU 分析回答“理论上能不能”，DMA selftest 回答“当前系统配置下实际上能不能”。

## L. Observability

## P. Leader Memory 深挖

建议下一阶段围绕一个可证明的 memory-lifetime invariant 展开：

```text
A physical page/BO may be reused
IFF
all GPU mappings are removed
AND all relevant TLB invalidations completed
AND all DMA/engine accesses drained
AND no stale fault/replay work from an older VM/reset generation can republish it
```

这条 invariant 可以直接贯穿 recoverable fault、migration、eviction、reset、P2P revoke 和 multi-GPU UVM，是 Memory Owner 当前最值得沉淀成设计文档与测试矩阵的长期主线。
